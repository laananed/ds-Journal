# T01 旧 blocks 转换交接

本交付是单 user block 保守子集的开发中结果，不是 T01 全部通过或 T12 收缩授权。基线 `codex/t01-check` / `2a454d5f8b61bb34c32d0cd0f675977717c0c011`。转换前需要独立测试和新 Codex 风险审核；实际批量转换还需全库备份与隔离恢复验证，个人库操作另行授权。

## 转换与限制

原 PATCH 在同一 writing Journal 的行锁和 revision CAS 下，验证单个 user block 的 UUID、严格字段、文本、候选 ID/作者和 R/U 相等；只写 JSON 和 revision，保留 content、旧 blocks、C 和 updated_at。事务异常走既有 rollback。存在任何 AI 请求、该文件评论或正文包含字母数字和空白之外的字符时保守拒绝；空数组、多块、AI、异常结构、投影不一致和混合元数据写入也拒绝。该条件十分严格，不能当作所有无风险记录均可转换。此方案不创建、执行批量任务或数据库迁移。

备份应覆盖完整库及序列，包括正文/blocks/JSON、身份、来源请求和引用、C、版本与时间；在隔离库恢复并比对一致后，冻结写入再按实际授权操作。保存旧 blocks 不是备份。未执行备份或恢复，本轮未访问数据库。

## 多块和交错 AI 的只读分析（未批准实施）

- 两个 user 块 `甲`、`乙`：旧 U 为 `甲乙`，当前 JSON 两块 U 为 `甲\n乙`。把它们拼成一个节点可能保留 U，却会改变块 ID 和边界；直接逐块转换会改变 C 对应位置。需定义边界及 C 的严格映射，并验证部分消费、删除、Unicode 和后续增量。
- user `甲`、AI reply `答`（带 request_id）、user `乙`：旧 U 仍是 `甲乙`，阅读投影含 AI 标识，JSON 的节点分隔与旧标识格式不同。AI 必须保留原 ID、request_id、原文和位置；`legacyText` 当前不容纳 request_id，不能直接使用它。可研究使用原生 AI 容器及精确投影适配，或经批准扩展兼容 schema 与前后端投影；两者都须证明 R/U、作者权限、复制和删除语义，不能凭颜色或文本猜来源。
- 旧引用和 review 快照可能引用旧投影与身份；应保留原格式标记及快照，通过精确映射或明确标记不可用来验证恢复，不能重写为未经证明的新位置。失效/未知来源先拒绝。C 仅在可证明原分析语义及边界不变时映射，不清空、不将全文标为已消费，也不自动重发。
- 拟议契约影响：API §2 节点/来源及转换命令，架构 §3 的 R/U 边界与 C 映射，前后端共享 fixtures、编辑/复制/恢复和旧请求一致性。以上均仅供决策，不代表已批准修改。
