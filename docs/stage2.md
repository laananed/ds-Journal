Stage 2 将 Journal Demo 升级为以 Inbox、Journal、Insight 三类 Markdown 文件为核心，支持一级 Folder、普通搜索、回收箱、简单内部跳转、分页和基础卡片 UI 的本地个人记录软件。

原阶段讨论中的 **Inbox → Journal 整理与基础操作记录已取消**。手动 Insight 现为必做；分页现为必做。不得继续执行旧提案。

## 2. 核心对象

| 对象 | 定位 | 日期与默认排序 |
|---|---|---|
| Inbox | 快速记录想法、任务、碎片和临时内容，可长期保留；不是 Journal 待整理区 | 04:00 业务日期；`created_at DESC` |
| Journal | 经历、日记、事件、复盘 | 保留可修改的 `journal_date`、同日多篇；`journal_date DESC, created_at DESC` |
| Insight | 认识、原则、结论、长期思考和认知沉淀 | 用户手动管理，不要求所属日期；`updated_at DESC` |

三类文件都有创建、列表、详情、修改和普通删除。创建/修改后数据以服务器回读结果为准。
Inbox 无整理状态、完成字段、颜色字段、过期规则或 Journal 来源关系；Checklist 由 Markdown 源码表达。

## 3. 通用内容规则

- `content` 必须有非空白字符，trim 检查后不能为空；空字符串、空格、换行、Tab 等纯空白无效。
- 原始正文最多 50,000 字符；前后端都校验。trim **仅用于判断有效性**，保存原始 Markdown，包括缩进、空行和尾部空格。
- `title` 最多 80 字符；前后端都校验，不自动 trim 用户自定义标题。
- 字符数按 Unicode 码点计数，前后端口径一致；中文和单个非 BMP 字符各算一个码点，不按字节或 JavaScript UTF-16 单元计数。
- Journal 标题可空；无标题继续用业务日期及同日编号显示，生成标题不写入 `title`。
- Inbox 新建时默认标题为当前 04:00 业务日期，用户可修改；**主动清空标题的规则见 P1**。
- Insight 建议填写可识别标题，但“建议”不等于必填；空标题允许，以“未命名 Insight”作展示回退，不写回 `title`。
- 摘要和省略只影响 UI，不截断数据库正文；详情和编辑器始终提供完整正文。
- 旧 Journal 不自动清洗或删改。响应读取不套用新请求的长度/非空限制；PATCH 仅校验实际提交的字段，允许用户逐项修复旧记录。
- 空 PATCH、只含被忽略字段的 PATCH 不写入；相同值不产生内容更新，`updated_at` 不变。真实内容、标题、日期或 Folder 变化才更新 `updated_at`。

## 4. Journal 显示编号

同日无标题记录按创建先后显示 `2026-10-07`、`2026-10-07 (2)`、`2026-10-07 (3)`。后创建的记录获得新编号；手工标题不参与计数。
列表仍按日期和创建时间倒序显示，**编号顺序与列表顺序是两件事**。同一创建时间以 `id` 升序决定编号次序。

创建新记录不得改变旧记录的编号。Stage 2 的编号必须在该日期完整数据范围计算，不能从当前页、Folder 或搜索结果计数。
所有 Stage 2 列表、详情、搜索、Folder、回收箱和内部链接使用一致的显示标题。
是否要求编号在删除、改日期或改为手工标题后仍永久保留，原提示词没有规定；见 P3。

## 5. Daily Inbox

业务日期与 Journal 默认日期使用同一套本机 04:00 规则：2026-10-08 02:00 的业务日期是 2026-10-07。

1. 进入 Inbox 时提供当日 Daily Inbox 的快捷入口。
2. 当日 Daily Inbox 尚未保存：显示默认日期标题和空编辑区域，**没有数据库记录，也不发创建请求**。
3. 用户输入有效正文并保存，才创建该日的 Daily Inbox；再进入时打开原记录。
4. 一天还可创建多个普通 Inbox，如“AI培训待办”“SeekJournal想法”；不要求标题唯一。
5. 修改 Daily Inbox 的标题、正文或 Folder 不改变其 Daily 身份；不能靠“标题刚好等于日期”识别 Daily。
6. 编辑器打开时确定业务日期；跨过 04:00 不重置正在输入的内容。再次进入或新建时重新计算。
7. Daily Inbox 被移入回收箱后，快捷入口如何处理见 P2；不得通过每日定时任务创建空记录。

## 6. Markdown 阅读与编辑

数据库存源码。编辑态用普通文本区域编辑源码；阅读态简单渲染：

```markdown
# 一级标题
## 二级标题
### 三级标题
- [ ] 未完成
- [x] 已完成
1. 第一项
2. 第二项
```

核心验收只要求上述语法。Checklist 阅读态不直接修改源码；复杂嵌套不属于验收。
渲染器自然支持的其他普通语法可以存在，但不增加核心范围。原始 HTML 不作为可信 HTML 执行；内部链接不在代码块/行内代码里激活。
不引入完整富文本编辑器。小型渲染依赖须在 S2-T12 中先提交具体用途与替代方案，再取得批准。

## 7. 一级 Folder

文件最多属于一个 Folder，也可不属于任何 Folder。Folder 支持创建、重命名、查看内容、文件移入/移出、删除空 Folder。
Folder 内容可混合三类文件，使用分页；只有有效文件显示在正常 Folder 页面。

非空 Folder 禁止删除。为保留恢复后的原 Folder 关系，**只要仍有任一文件引用该 Folder，包括回收箱中的文件，就不是空 Folder**。
因此页面虽然只显示有效文件，也需说明删除被拒绝可能是因为回收箱内容仍占用；不实现级联删除或偷偷清空关系。
文件移出/移入由其编辑表单的 Folder 字段保存，遵循相同 Dirty State 规则。
Folder 不进回收箱，不支持子文件夹、颜色、图标、拖动排序或智能 Folder。

## 8. 简单内部链接

阅读态识别 `[[文件标题]]`，目标可为任一有效 Journal、Inbox 或 Insight。
Lead 的最小匹配设计：**按当前显示标题精确匹配**，不做模糊搜索、大小写归一化或 trim；Journal 自动日期标题也可作为目标。用户手工写出的相同标题保留重复候选。

- 一个目标：打开该文件真实详情。
- 多个目标：显示选择列表，至少含类型、显示标题、Journal 日期或其他文件创建时间。
- 零个目标：显示找不到目标，不自动创建文件。
- 已删除文件不参与匹配，回收箱阅读不提供新增编辑关系。
- 文件改名后旧链接可能失效；永久删除后该对象不能再命中。同标题其他有效对象仍按匹配规则处理。

不实现 Heading/Block/段落跳转、Backlink、图谱、引用表、自动重命名引用。
点击前按最新数据解析，候选选中后详情若已删除，应显示不存在。

## 9. 搜索

覆盖三类文件的原始 `title` 和原始 Markdown `content`，排除回收箱。
中文普通子串，英文忽略大小写；空白分隔多个关键词，关键词之间 AND，各关键词可以分别命中 title/content。
例如 `AI 培训`：必须同时命中 AI 与培训，允许 AI 在标题、培训在正文。
`%`、`_` 等字符按普通文本处理，不暴露 SQL 通配表达式。

Lead 确定排序为 `updated_at DESC`，相同时间按类型固定顺序 Journal、Inbox、Insight，再按各自 `id DESC`。
支持全部/Journal/Inbox/Insight 最小类型筛选；没有高级搜索表达式或 relevance ranking。
空搜索词不展示全库，显示输入关键词提示。分页作用于全体匹配结果，不是三种类型各取 20 条拼接。
Journal 的自动显示标题不等于真实 `title`；本期搜索范围不额外扩展到业务日期、Folder 名或渲染后的文本。

## 10. 分页与 UI

所有文件列表、按日期列表、Folder、Search、Trash 均 20 条/页，提供上一页/下一页；Daily 快捷入口不依赖所在分页。
条件、搜索词或 Folder 改变回第一页。删除、移出 Folder 等导致当前页超范围，回最近有效页；无结果时保持第 1 页空状态。
排序加稳定的 id 次序，避免相同时间项随机跨页；本期不做快照分页，数据变化后刷新即可。

基础导航：Inbox、Journal、Insight、Search、Trash；Folder 有独立入口。
卡片显示标题一行、正文摘要三行、日期/时间、必要类型信息；整个卡片可点击，保留键盘可操作的打开入口。
提供加载、失败重试、空状态、基础响应式、Markdown 阅读样式；不强制 Dashboard。
保留 Stage 1 的防重复提交、请求过期处理、保存失败保留输入、写成功与列表刷新失败分开反馈。

## 11. 回收箱

普通删除改为软删除，三类文件均进入回收箱，并从正常列表、Folder、Search、内部链接和普通详情隐藏。
回收箱可单条查看、恢复、永久删除；不可编辑或修改 Folder。回收箱列表按 `deleted_at DESC` 分页。

移入/恢复只改变删除时间，**不改变 `updated_at`**。恢复保留原 ID、title、content、Journal 日期、创建/修改时间和 Folder 关系。
永久删除须明确确认不可恢复；只作用于回收箱中指定的一条记录。
不做 30 天自动清除、后台定时任务、批量恢复/删除或清空回收箱。

## 12. Dirty State

新建/编辑时，title、content、Journal 日期或 Folder 相对初始值发生变化即为 Dirty。
切换文件、模块、列表、搜索结果、Folder、内部链接和 Daily 入口，都统一经过离开检查：
“当前内容尚未保存，确定离开？”
选择继续编辑则保留输入；确认离开才丢弃本次未保存改动。保存失败不清除 Dirty，保存成功才重置基线。
新建 Daily 的默认日期标题本身不算用户改动；没有用户输入的空编辑器离开不提醒。
无自动草稿、LocalStorage 草稿或刷新后恢复承诺。

## 13. Non-goals

AI、AI Insight、Inbox → Journal、Inbox 整理状态、操作记录/操作历史表/时间线、内容版本历史、自动任务排序、Inbox 颜色状态、高级 Markdown 编辑器、图片、附件、标签、Journal Merge、复杂内部链接、Backlink、图谱、多级 Folder、语义搜索/Embedding/RAG、云、登录、多用户、权限、同步、Android、30 天自动清理、批量回收箱操作、完整品牌 UI。
也不要求 WYSIWYG、点击 Checkbox 改源码、自动移动已完成任务、表格、LaTeX、Block 编辑器、拖动、手势、标题折叠、高级动画。
对象的 created_at/updated_at/deleted_at 是必要字段，**不构成操作历史功能**。

## 16. 可选体验建议（未纳入核心验收）

1. 将“今日 Inbox”放在 Inbox 顶部，显示保存状态；比从分页卡片里寻找当天文件更直接，属于已确认“容易找到”的具体呈现建议。
2. Folder 删除被拒绝时显示“仍有文件引用，可能在回收箱”，并给出回收箱入口；减少正常页面看起来为空却删不掉的困惑。
3. 增加 `Ctrl+Enter` 保存快捷键；按钮仍保留。这是可选交互，不应为此引入快捷键库。
4. 阅读/源码编辑使用清晰的两个入口，避免让用户误以为点 Checklist 就会保存；若希望编辑中实时预览，再单独确认，不扩展成本期必须功能。

前两项可在已有信息架构范围内采用；快捷键与实时预览需用户决定是否纳入 Task。不要提前实现未来 UI 系统。
