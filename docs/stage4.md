## 2. 术语与已确认决定

| 内部标识 | 产品含义 | 前端显示 |
|---|---|---|
| `journal` / `journal_kind=writing` | 普通 Journal；不限每日一篇 | Writing 入口显示“写作”，文件仍为日记 |
| `journal` / `journal_kind=set` | Set The Day，日初 Ritual | **开始今天** |
| `journal` / `journal_kind=end` | End The Day，日终 Ritual | **结束今天** |
| `insight` | 观点文件，无业务日期 | Insight |

Writing、开始今天、结束今天均属于 Journal，沿用 Journal ID、Folder、Trash 及版本机制；不新增第三张文件表。Insight 共用 Tiptap，本期 Go Deeper、Minds Comments 仅对 Journal 开放。Inbox/Daily 功能、API、当前模型和表全部移除，现有 Inbox 允许物理删除，其数据安全契约见 API §11、架构 §10。

以下八项已确认决定已收口，不再以“待产品确认”阻塞：

1. 文件与 AI：采用上表。其他文件中的 Checklist 不自动进入开始今天。
2. 恢复：不做完整版本历史。开始今天与结束今天均支持完整替换恢复、左右对照后手动选择内容复制到当前同类 Ritual；CAS 冲突保留本地草稿。
3. 同步：主动加入结束今天后，目标文字、完成状态双向同步，开始今天为权威来源；删除目标或软删/永久删除任一关联文件时解除关联，保留 End 快照和回答。恢复不自动重连，需用户再次主动关联。
4. 自动 AI：两个独立开关默认关闭。15 秒停顿、80 Unicode 码点增量、60 秒冷却是可调整的初始技术参数；只由真实用户输入触发。Go Deeper 使用行内占位和原位回复；Minds 使用少量预置方案。
5. 日期：固定 `Asia/Shanghai`、04:00 换日；Ritual 在创建草稿时捕获业务日期，首次落库后也不可修改。普通 Journal 可改日期；跨日不丢输入。
6. Markdown：优先正文、作者身份、检查点和引用关系安全，不要求旧源码逐字往返；无法安全转换的记录保留原始内容及恢复能力，不能静默丢失或重复触发付费 AI。

7. 结题日程与 Set 目标独立管理，各自创建、完成和删除，不自动同步；不影响 Set 与 End 的主动关联同步。日程是新增 C01，非原 Stage 4 Task。
8. Journal 未提交草稿需本地持久化，关闭或意外退出后可发现并由用户选择恢复；不能静默覆盖服务端较新版本。它不是每次自动保存的版本历史，也不保证突然断电时最后一次输入必然恢复。

## 3. UI 与导航

高度参考 Mindsera 桌面 Web 的简洁留白、Dashboard、写作入口、日初/日终 Ritual、Go Deeper 和评论体验；不照搬其账号、语音、商业方案或长期记忆功能。

主导航覆盖概览、写作、日记、Insight、文件夹、搜索、回收箱、设置。左侧主导航旁的上下文区域：Writing 展示今天普通写作文件及预览；开始今天/结束今天展示当前对应问题模板；正文在主区域，评论按需出现在右侧。左侧模板不额外展示历史模板列表。保留键盘操作、焦点可见、加载/空/失败/冲突状态及基础窄屏可用性；Android 作为额外结题任务 C02，不计入原 Stage 4 范围。

提供浅色、深色与跟随系统的外观选择，使用现有 CSS 能力和设计变量，不为主题增加 UI 框架。完整蓝色大肥鱼主题不在范围内。普通文件的查看、归类、搜索和回收箱入口不能因 UI 重构丢失。

## 4. Writing 与今日总览

首次进入 Writing 默认打开一个未落库的空普通 Journal 草稿。应用内返回时恢复该会话，不能每次切页都新建数据库行或丢掉未提交内容；用户点击新建才产生另一份草稿身份。首次有效保存使用稳定创建键，之后使用真实文件 ID 与 CAS。

Writing 左侧列表仅包含当前业务日期、有效的 `writing` Journal，显示标题、正文预览及保存状态，点击继续编辑；可明确新建另一篇。日记总列表仍能打开历史日期文件。

Dashboard 今日总览按当前业务日期动态读取普通 Journal、开始今天、结束今天，并显示两种 Ritual 的进入/继续入口。它是动态列表，不自动生成“今日汇总”、复盘或其他文件。已有用户主动确认保存的 AI 复盘 Journal 仍是普通 Journal，不与总览混淆。

仅打开页面、查询缺失 Ritual 或点击插入空问题模板，不创建空 Journal。首次有效用户正文/目标，或用户主动将真实目标加入结束今天的操作，才形成有业务内容的文件。问题和回答未写完也保存在应用会话中；新建无效输入不伪装成数据库已保存。

## 5. 业务日期与 Ritual

业务日覆盖上海时间当日 04:00 至次日 03:59:59…，不能用 UTC 日期或电脑当前时区替代。创建 Ritual 草稿时捕获带时区时刻并计算所属日期；跨 04:00 后继续原草稿，日期不自动跳转，也不偷偷归到新的名额。未保存内容继续保留并按创建幂等/名额冲突处理。刷新后的已保存内容按数据库日期恢复。

每业务日期最多一篇有效开始今天和一篇有效结束今天。标题、Folder 和正文可编辑；类型与业务日期不允许 PATCH。不能通过改标题、移 Folder 或通用 Journal 接口绕过唯一约束。旧普通 Journal 不因标题相同被推断为 Ritual。

开始今天/结束今天各有一份当前模板，0～4 个自定义问题；四问上限作用于当前模板，不回溯删除或截断历史正文。模板为空时显示添加问题入口，不自动生成问题或调用模型。点击问题才插入正文；插入内容保存当时文字快照，用户答案为独立正文。后续模板增删改、换序不回写任何已插入内容。历史日期的有效 Ritual 正文仍可编辑；回收箱文件仍按 Trash 规则只读。

## 6. 删除、冲突与恢复

两种 Ritual 均支持软删除、普通恢复、永久删除，沿用 Journal 生命周期及明确确认。软删除释放对应有效名额，同日可再创建一篇；旧文件保留原日期、ID 和正文。

恢复旧文件发现同日同类已有有效文件时：

- 保持当前文件，取消恢复：双方不变。
- 完整替换恢复：用户确认后，现有效文件移入回收箱，旧文件恢复原 ID；在一个事务完成，不能先永久删除现有文件。开始今天、结束今天行为相同。
- 左右对照复制：旧文件在左侧只读，当前同日同类文件在右侧可编辑；用户手动选择内容复制到当前文件。不是自动合并或智能取舍，取消不写入。原旧文件仍在回收箱，当前 ID 保留。受控复制保持 AI 来源身份；复制目标使用新目标 ID，不自动建立跨文件同步。

完整替换/复制前明确展示对象、日期与版本，CAS 变化返回冲突。应用保留本地草稿和服务器版本供用户选择，不静默刷新覆盖。命令执行期间新增的输入仍归原会话，不能因为恢复切换 ID 而被覆盖或转移到另一文件。

这里的恢复不建立每次自动保存版本历史，不增加跨日期 Ritual 合并或字符级自动合并系统；未提交 Journal 草稿的本地恢复按 §10 执行。

## 7. Checklist 目标与结束今天回顾

开始今天内普通用户文字转换为 Checklist 后形成目标，具有稳定 `goal_id`。其他 Journal/Insight 的普通 Checklist 只属于原文件。完成/未完成的展示置底是派生排序，不改正文存储顺序、目标 ID 或 AI 用户事实顺序。

用户主动将目标加入同一业务日期的结束今天后才建立同步；同一目标重复加入同一结束今天不产生重复回顾。若结束今天不存在，该主动操作可原子创建带真实目标回顾内容的文件，不先建立空占位文件。

目标文字、完成状态可从两端操作，提交到开始今天后再投影到结束今天。系统生成回顾标题随目标文字更新；用户对目标的回答使用独立正文，任何同步均不得改写。失效目标不能从结束今天修改出一篇新的开始今天。

| 来源事件 | 关联与结束今天表现 |
|---|---|
| 未主动加入结束今天 | 没有关联，不写结束今天 |
| 有效目标改文字/勾选 | 原子同步指定字段；用户回答不变 |
| 删除目标或转换回普通文字 | 保留结束今天回顾及回答，标记来源不可用；不按相同文字重连 |
| 软删除开始今天 | 解除关联，结束今天保留最后快照和回答，标记来源不可用 |
| 恢复同一开始今天 | 不自动重连；用户可主动重新关联，原快照和回答不丢失 |
| 恢复另一篇或复制目标 | 不继承旧关联；用户主动加入才关联 |
| 永久删除开始今天 | 保留结束今天已保存回顾和回答，来源不可用，清理敏感 AI 附属数据 |
| 软删除结束今天 | 解除关联；回收箱保留快照和回答，恢复后不自动重连 |

并发修改、长度上限或任一数据库失败导致整个关联写入回滚，不能只成功一端。历史日期的有效 Ritual 同样适用。

## 8. 富文本、兼容与作者

保留文件统一采用 Tiptap；JSON 为正文权威，后端生成阅读/搜索 `content` 投影，不从显示颜色、Markdown 标记或评论文字猜作者。

保留用户、AI 回复、AI 总结与系统模板/镜像的身份。AI 总结可编辑但仍保持 AI 来源；局部回复的内容/来源由后端保护，允许明确删除。普通外部粘贴作为用户主动输入，不能伪造系统或 AI 身份；受控恢复复制由后端验证来源。

普通编辑上限仍为 50,000 Unicode 码点阅读投影；旧超限/空白数据可读，未改正文时可改允许的元信息，不截断。无法安全转换时在 Tiptap JSON 中保留原文兼容节点与作者，不以空白、截断或丢掉 AI 块完成迁移。原始 HTML 不作为可信 HTML 执行，内部链接和外部引用继续安全阅读。

正文/作者/用户事实投影、旧检查点与来源引用分别核验；迁移和格式化本身不请求 AI、不清空检查点制造重复分析，也不将未分析的新正文写成“已消费”。转换失败可恢复原始内容，不能用整库重建掩盖。

## 9. Go Deeper 与 Minds Comments

Go Deeper 沿用用户正文增量、旧文修订、独立问题、有限近期上下文、无输入零调用等 Stage 3 语义；默认简短启发式回应，完整总结仍走明确复盘流程。调用使用当时已保存快照，行内稳定占位允许下方继续写；完成回到原占位，不覆盖新增正文、不强制改为侧栏。

Minds Comments 使用免费自定义 Mark 与侧栏，先提供“温和陪伴 / 换个角度 / 思维陷阱”三个静态预置方案，默认温和陪伴；没有历史记忆方案、复杂自定义 Mind 管理、评论续聊或市场。手动可分析当前 Journal 或选区；自动只分析本次新增/修订的用户范围。一个功能请求可返回所选预置评论，不能暗中为每个预置再发独立付费请求。

锚点必须与调用时用户正文对应；返回时范围已修改或移除则保留侧栏结果并说明无法定位，不凭重复词匹配到别处。评论不作为用户事实、不推进 Go Deeper 检查点，删除评论/回复不撤回 Token。

两种自动开关持久保存且独立，默认关闭。只在当前可见编辑 Journal 中，由真实用户文本输入（含 IME 完成、粘贴、用户撤销重做造成的文本变化）调度；系统回写、AI 回复、模板插入、格式化、目标同步、恢复复制、初次加载和切页不启动新付费调用。用户后续真实输入可重新调度。切页/隐藏取消尚未执行的自动触发，在途请求继续受应用管理。

初始参数和去重语义由 API §8 维护，允许技术调优但必须同步文档/测试。失败、冲突、unknown 不静默换键重发；用户明确重新请求才可能再次计费。自动和手动均使用原位占位、快照、作者、计量与安全契约。

## 10. 保存、请求恢复与保留能力

应用级编辑会话和请求管理独立于页面挂载，保存/AI 中可立即切换文件、模块、列表、内部链接、复盘和设置。原文件继续保存，失败显示可返回入口；跨文件迟到响应不能切换当前文件或覆盖草稿。新建响应丢失仍用原键与首次 payload 重放，再 PATCH 较新输入。

Journal 未提交草稿在浏览器本地持久化，重新打开时发现并展示恢复、稍后处理、明确丢弃等选项；有服务端文件时先读取并比较基线版本，变化或不可读取时保留双方内容，不自动提交或覆盖。新建草稿保留创建键与首次请求以处理响应丢失。多标签草稿独立；本地保存失败、空间不足或权限受限须清楚告警并保留内存输入。持久化结果只表示本机草稿已保存，数据库提交成功才能显示服务器已保存。

本地草稿可能包含私人日记，由同浏览器同源存储；共享设备用户可访问，浏览器清理、隐私模式或存储驱逐可使其消失。用户可明确清理；不记录 Key、不上传/写日志、不承诺加密或突然断电时最后输入必然恢复。它不是版本历史或跨设备离线同步。请求恢复索引仍只存 ID/类型/来源；重开先 GET 状态，不自动重新付费。细节以架构 §4、API §10 为准。

保留单/多篇复盘、最多 7 个不同业务日期/15 个 Journal、一次确认保存、独立 Insight 添加与另加一份；本期不把 Insight 加入复盘源。保留 Folder、Search、Trash、内部链接、幂等、CAS 和匿名累计 Token；搜索仍为普通关键词查询，无 RAG。旧内部链接到 Inbox 按当前精确标题解析结果处理；没有其他有效候选时显示来源不可用，不自动新建或改写文字。

## 11. 非目标

原 Stage 4 不包括 Android（结题新增 C02 单列）、云部署/登录/多用户协作、RAG/Embedding/长期记忆、语义去重、复杂情绪分析、完整蓝色大肥鱼主题、完整版本历史、CRDT、离线同步、复杂 Mind 管理、评论聊天、任意附件/图片/语音、后台任务队列及自动生成今日汇总。技术栈和模块化单体边界不变。
