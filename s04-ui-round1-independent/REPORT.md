## 四、缺陷详情

### 缺陷 1（失败）：速记页空白草稿导致离开被误拦截

**复现**（桌面 1440×900，真实生产构建 + 合成 Mock，**全新 Chrome 配置**亦复现）：

1. 打开首页（当天无计划）→ 点「速记」；
2. 不做任何输入，等待 0.4 s 或 3 s 均可；
3. 点左栏「记录」，或点左上品牌标识回「概览」；
4. 观测：弹出「最新改动还没保存成功，确定离开？」，正文说明「自动保存失败或出现版本冲突…」，`aria-current` 仍停在「速记」，主区不切换；请求日志为 **0 条写请求**（连 `POST` 都没有）。

**影响**：新用户从首页主入口进入速记后，无法直接返回或切页，必须先确认「丢弃」；文案把"没有内容可保存"误报为"自动保存失败/版本冲突"，会让人误以为数据出问题。

**根因（逻辑层已复现，非猜测）**：`frontend/src/state/editSessions.ts::planWrite` 在 `fileId === null` 分支中，先判 `draftEquals`、再判 `isSavable`。用真实函数实测：

```
空白草稿 draft={doc,content:[]} / baseline.content_doc=null → {"kind":"blocked","reason":"invalid"}
空白草稿 draft === baseline                              → {"kind":"idle"}
有正文（isSavable=true）                                  → {"kind":"create"}
```

即：编辑区挂载后把 `content_doc` 从 `null` 规范化为空文档，造成"有改动"；空白又不满足 `isSavable`，于是 `blocked/invalid`，`App.tsx::navigate` 统一按「保存失败」弹出阻断弹窗。

**归属**：`WritingPage.tsx`、`editSessions.ts`、编辑器本轮均**不在 diff 内**，属既有逻辑；本轮把「速记」变成首页主入口，使该路径成为主流程。按规则不在测试中修复，交开发者与 Codex 判断（可选择：空白草稿视为 idle，或对 `invalid` 使用"无内容可保存"的非阻断语气）。

### 缺陷 2（部分）：空白速记留下本机未提交草稿

进入速记后即使不输入，页面顶部出现「本机还有 1 份未提交的草稿（不含服务器已保存的内容）」；`本地草稿（1）`。服务器零记录。与「空白稿不会产生记录」的用户预期不一致，也会让上述拦截更容易被误解为"真的丢了东西"。

### 缺陷 3（部分·无障碍）：「更多」子项缺 `aria-current`

进入日程/AI 复盘/历史收件箱/文件夹后，`[aria-current="page"]` 为空数组，仅「更多」按钮 `data-active="true"` 变色。视觉可辨，读屏不可辨。
