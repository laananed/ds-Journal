# S04-T12 隔离数据库验证方案（未执行）

本方案不是写库许可或备份证明。无业务作用的未提交空过渡 revision 已移除，当前代码 head 是 `c01a7e421b50`；删除测试可执行前必须另行完成实际删除迁移、前后端统一切换及独立风险审核。

1. 预约专用测试库及独占时段，确认 `current_database()`、实际服务和 Alembic 连接目标、revision、其他连接、既有表和记录，检查 pytest fixture 与清理脚本。`seekjournal_test_03` 上次有其他连接及既有 usage；不得假定现在已空闲，不得清理该行。发现陌生对象、无法确定归属、连接或目标时停止。
2. 使用本轮唯一标识新建私有 schema，建立 manifest，记录 schema、每个合成文件/请求/用量/评论 ID 和独立备份路径。仅在已核验的专用库中对该 schema 从 M3 升级到 M4A，建立纯用户、多块、AI 交错、异常 blocks、引用/评论、Folder、回收箱、已存总结和 mixed Inbox/Journal 请求；为每个对象记录正文、作者、R/U/C、引用、时间、序列及账本摘要。不得借测试写入个人库，不得重置序列。
3. 对该 schema 做 PostgreSQL 一致性备份，记录备份文件散列；在同一独占测试窗口内新建另一个带本轮标识的空恢复 schema 或另行分配的独占测试库执行恢复（使用相应 pg_dump/pg_restore 选项，先核对目标与归属）。逐项比较上述摘要及 schema/revision。不能证明备份与恢复有效时停止后续收缩。
4. 未来收缩迁移完成后，通过数据库会话与进程级证据确认旧执行者已停止或隔离、无其他写入者；构造 pending、unknown、未知来源、未知引用和未安全转换旧文，分别验证收缩迁移拒绝、事务回滚及原文/用量不变。故障注入发生在事务中不同阶段，记录升级前后快照和 revision；不把 Mock 当作数据库证据。
5. 在批准的可升级实现出现后，清除仅本轮构造的阻塞条件，验证混合来源整条删除及快照不可读、Inbox C 清除、Journal C/内容/引用/Folder/usage 不变。旧客户端和迟到执行使用受控合成旧进程或会话，验证无法恢复私人快照且已产生计量得以保留；旧进程归属或隔离无法证明时不执行删除。
6. 复核备份后执行隔离恢复，比较正文、身份、作者、R/U/C、引用、记录时间、序列及 usage；DROP 后普通 downgrade 不构成恢复。对于切换后新增数据，先备份并制定合并保护，不以旧备份覆盖。
7. 收尾只删除 manifest 中本轮自建且已核验归属的 schema（包括恢复 schema），删除前复核其精确名称、所属库和其他会话；不清理 public、不改既有记录、不重置序列。核对自建对象消失、既有对象与计量摘要不变。保留脱敏命令、退出码、结果和故障证据。

独立测试者必须是未参与实现的新对话；另需新 Codex 进行旧数据、隐私和迁移风险审核。真实库备份、升级或写入须用户单独授权，且先完成隔离恢复验证。
