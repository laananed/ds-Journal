## 3. 发现的问题

### P1（中）Set／End 在中文输入法组合期就把未上屏拼音写入服务器

- 现象：在「开始今天」输入 `前缀。` 并保存后，用输入法打 `nihao`（未选词、未上屏），约 900ms 后服务器版本 +1，正文变成 `前缀。nihao`；「结束今天」同样复现。
- 对照：同一操作在 Writing 页**不会**写入拼音（服务器无 `nihao`，状态「未提交到服务器」）。
- 代码依据：`RitualPage.tsx` 只有**读取** `session.imeComposing`（自动保存判断第 344 行、自动目标判断第 880 行），**从未调用** `editSessionStore.setComposing`，也没有 `onCompositionStart/End`；`WritingPage.tsx` 第 1016–1017 行在正文外层注册了组合事件。因此 Set/End 上的两处 IME 守卫恒为 false，属未被激活的守卫。
- 影响：组合期保存会把拼音片段写进服务器（短暂但不正确的内容）；若用户在组合期切页/关闭页面，本机草稿与服务器都会留下拼音。与架构 §4.1「不把半个拼音写进服务器」不符。
- 复现：Set 页输入并等待保存 → 输入法组合 `nihao` 不选词 → 1.5s 后查 Mock 状态（`/__mock/state`）或真实接口。
- 证据：`run6-results.json`（IME Set / IME Writing）、`run7-ime.json`、`r6-02-ime-set.png`、`r7-ime-开始今天.png`
- 未验证：真实输入法上屏后是否能正确覆盖为中文（无头环境无法完成真实上屏，`Input.insertText` 未能替换组合文本，DOM 仍显示 `nihao`）。

### P2（中）Writing 保存进行中点导航：按钮可点但页面不动，且无任何反馈

- 现象：注入 3s 的 PATCH 延迟后，输入文字并点「概览」，导航按钮 `disabled=false`，点击后 3s 内仍停在写作页，期间没有任何「正在保存／请稍候」提示；保存完成后才自动跳转。
- 原因：`App.tsx` 的 `navigate()` 先 `await flush()`，flush 内部等待在途写请求；导航被串行化到保存之后，但界面没有对应的等待态。
- 影响：慢网络（或后端抖动）下表现为「点击失效」，用户会重复点击或以为页面卡死。产品 §10 要求「保存/AI 中可立即切换模块」。无数据丢失。
- 复现：`POST /__mock/fault {"patchDelayMs":3000}` → 写作页输入 → 1.1s 内点「概览」→ 立即检查仍在 `.writing-page` → 3s 后自动离开且内容已落库。
- 证据：`run3-results.json`（C1）、`r3-01-nav-slow-save-click.png`、`r3-02-nav-slow-save-after.png`

### P3（低—中）Set／End 保存进行中把全部导航按钮置灰且不解释

- 现象：Set 保存请求在途时，「概览／写作／开始今天／结束今天」全部 `disabled=true`；保存完成后恢复。
- 原因：`RitualPage` 通过 `onBusyChange` 把 `inFlight` 上报为全局写锁，`App` 用它禁用导航。
- 影响：比 P2 更「诚实」但同样与「保存中可立即切换」不一致；慢网络下用户无法切页，且没有说明为什么按钮不可用。
- 证据：`run9-results.json`（N）、`r9-01-set-nav-during-save.png`

### 观察项（非缺陷，待产品确认）

- O1 **刷新后默认草稿**：刷新 Writing 页面会得到一份新的空白草稿，不自动打开最近一篇（已保存内容可从侧栏打开）。`docs/stage4.md` §10 只承诺「未提交草稿重开时发现」，未承诺刷新恢复已保存正文，故记为行为说明而非缺陷；若希望贴近「继续写今天这篇」，需要产品先明确。
- O2 **本机草稿面板的计划延迟**：Writing 面板对已有服务器文件的记录先显示「尚未读取服务器版本」，点「恢复」后才探测并给出冲突对照；`RitualPage` 则会预探测。两者不一致，但都能在一步内得到正确结果。
- O3 **恢复后不自动提交**：D3/D4 恢复后状态为「未提交到服务器」，需用户点「立即保存」或继续输入。这是「不静默覆盖服务器」的有意设计，提示文案已写明。

## 6. 结论

- 日常主路径（新建、编辑、自动保存、切页返回、刷新后从侧栏打开、失败保留与重试、冲突对照、本机草稿恢复、Set/End 编辑保存、清单转目标与 End 回顾）**在 Mock 环境下全部可用，未发现输入丢失或重复创建**。
- 需要处理的两个实际问题是 **P1（Set/End 组合期写入拼音，守卫未接线）** 和 **P2（保存中导航无反馈）**；P3 与 P2 同源，建议一并决策导航与保存的交互契约。
- 本轮未修改任何产品代码；未提交、未合并、未推送。上述问题若需修复，应先由 Codex 确认归属与契约，再在独立分支实施并做独立复测。
