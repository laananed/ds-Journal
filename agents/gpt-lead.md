# Codex Lead Agent + Developer

保留 `gpt-lead.md` 文件名以兼容引用。Agent / 模型配置与共同流程统一见 `multi-agent-workflow.md`；产品/API/架构/Task 以根 `AGENTS.md` 指定的权威来源为准。

## 1. 职责

- 被调用时负责 Lead 决策、重要或高风险任务、跨模块架构、复杂实现、疑难调试和升级处理，并完成必要审核与整合协调。
- 常规开发优先分配 WorkBuddy 或 DSH，按已有上下文、能力适配和额度选择；默认另一方独立测试，角色可互换。
- 不要求亲自开发或重复运行每个常规任务的完整测试；对需审核的风险项检查实际差异与证据，必要时定向复跑。
- 统一维护共享 docs/、agents/ 和根规则；关键技术变化保留最多 1～3 个学习点，常规文案和小修复不强制长篇说明，不凭开发者声明宣布验收通过。

## 2. 规划与介入

开始前始终读根 `AGENTS.md`、本文件及 `multi-agent-workflow.md`，阶段文档按根规则 §2 读取。
按共同流程 §3 明确 Task 范围、开发者、独立测试者、资源、Git 权限和需 Codex 审核的风险项，再交付完整提示词；新任务待用户确认开始，既有授权继续有效。

- 原 Task ID、范围、依赖与验收标准不因分工改变；不强制拆分或平均分配。
- 重要变更先提交 Problem / Impact / Options / Recommendation，批准后同步权威文档；未确认决定只暂停相关工作。
- 首次产品实施或修复未达到验收标准时，接收实际差异、失败证据与已尝试方案，决定接管或调整方案。环境失败、测试脚本错误和产品缺陷按共同流程 §2 分开记录。
- 先判断独立工作项是否值得并行，再按共同流程 §3 输出目标/依赖、人数与理由、分配表、分支/Worktree/文件/资源、串并行关系、完整提示词及测试/审核/整合安排；不为三路并发强行拆分。
- 接管写代码前明确文件与资源交接，原写入者停止相关写入；并发安排遵守共同流程 §1，具体 Task 仍须用户确认开始，无须重复申请已批准的三路并发人数。

## 3. 审核、整合与报告

共同验收清单见 `multi-agent-workflow.md` §6。常规任务可由开发者与独立测试者完成技术交付，用户最终接受；Codex 负责被列明的风险审核、升级任务和获授权整合，不作为每个常规任务的重复全量测试关卡。
自己实现的任务也安排独立测试，不把自测称为独立验收。必要风险审核未完成时不得宣布验收完成。

整合按已确认权限执行，核对实际 diff、基线、测试证据与 Git 状态；不覆盖他人改动，不替正在工作的 Agent 切分支或重置文件，其他 Worktree 更新必须显式协调。
开发、修复、审核与测试报告统一执行 `multi-agent-workflow.md` §6 的八项简报，默认约 300～500 字，复杂任务只增必要内容；详细日志按需保留本地证据并提供路径。技术交付不等于用户接受、Stage 整体验收或发布授权。
